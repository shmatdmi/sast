# Каталог правил в PostgreSQL

Схема `sast_rules` находится в существующей базе приложения. Миграция
`0005_little_silvermane` создаёт четыре таблицы и импортирует снимок текущих
1000 статических правил. Шесть дополнительных проверок потока данных остаются
алгоритмами движка и не входят в этот каталог регулярных выражений.

Миграция `0006_http_rule_catalog` добавляет снимок из **2000 правил**, сохраняя
исходный набор из 1000. Новые 1000 определений — сочетания 100 API и 10 каналов
HTTP-ввода, подробнее в [каталоге HTTP](security-rules-http.md).
После обеих миграций в пустой БД: 2000 правил, 2000 версий, 2 набора и 3000 связей.

Миграция `0007_http_rule_catalog_5000` добавляет снимок из **5000 правил**.
HTTP-набор расширен до 400 API × 10 источников ввода для JavaScript/TypeScript,
Python, PHP и Ruby. После всех миграций: 5000 правил, 5000 версий, 3 набора,
8000 связей; старые снимки сохранены.

Миграция `0008_framework_rule_catalog_20000` добавляет снимок на **20000 правил**.
После миграций до 0008 в пустой БД: 20000 правил, 20000 версий, 4 набора и 28000 связей.
Состав дополнительных вариантов описан в [каталоге фреймворков](security-rules-framework.md).

Исходный набор: `builtin-1000-5837bdc59459`. Контрольная сумма состава:
`5837bdc594596ac0ffbb833a3b0d8c69835f2130952b61454f63e5d3cbd7f71a`.

| Таблица | Содержимое |
|---|---|
| `sast_rules.rules` | ID и исходные метаданные правила: название, языки, категория, CWE и OWASP |
| `sast_rules.rule_versions` | Полное определение конкретной версии правила в JSONB и SHA-256 определения |
| `sast_rules.rulesets` | Именованные снимки каталога, SHA-256 упорядоченного состава и число правил |
| `sast_rules.ruleset_items` | Связи набора с точными версиями правил и исходная позиция каждого правила |

Определение версии содержит описание, критичность, уверенность, рекомендации,
ссылки, языки, CWE/OWASP, категорию, область поиска и регулярные выражения.
`pattern`/`patternFlags` и `exclude`/`excludeFlags` хранят источник выражения
и его флаги отдельно; отсутствующее исключение представлено `null`.
Восстановление: `new RegExp(definition.pattern, definition.patternFlags)`.

Повторный импорт не создаёт дубликатов и не заменяет существующие определения.
Изменение правила создаёт новую версию и новый снимок; предыдущие снимки
сохраняются. Метаданные в `rules` описывают первое импортированное определение;
для просмотра конкретного набора используйте `rule_versions.definition`.
Импорт выполняется в транзакции и сверяет все определения, порядок и число
участников. При расхождении вся транзакция откатывается.

## Импорт и просмотр

Миграции применяются обычной командой `npm run db:migrate`, включая исходный
снимок. Для повторного импорта текущих правил после миграций:

```bash
DATABASE_URL=postgresql://... npm run rules:seed
```

Для экспорта SQL без подключения к БД:

```bash
npm run rules:seed -- --sql ./catalog.sql
```

SQL уже содержит `BEGIN`/`COMMIT`; запускайте через `psql -v ON_ERROR_STOP=1`.

```sql
SELECT name, rule_count, content_hash FROM sast_rules.rulesets;

SELECT item.position, item.rule_id,
       version.definition->>'title' AS title,
       version.definition->>'severity' AS severity,
       version.definition->>'pattern' AS pattern
FROM sast_rules.ruleset_items item
JOIN sast_rules.rule_versions version ON version.id = item.rule_version_id
JOIN sast_rules.rulesets ruleset ON ruleset.id = item.ruleset_id
WHERE ruleset.name = 'нужный набор'
ORDER BY item.position;
```

## Граница текущего изменения

Каталог создан для хранения и версионирования. Сканер пока использует встроенные
правила; изменение записей в БД само по себе не меняет анализ. Загрузка наборов
из БД через API, кэширование и сохранение версии набора в результатах требуют
отдельного подключения. Анализ кода в браузере продолжает работать как раньше.

## Проверка PostgreSQL

`npm run test:rules-db` использует только отдельную пустую локальную БД
`codesentry_rules_test`, указанную в `SAST_RULE_TEST_DATABASE_URL`.
Проверяются миграции, точное соответствие всех 150036 определений, сохранение прежних снимков, Unicode,
кавычки и обратные слеши, повторный импорт, новые версии, внешние ключи
и атомарный откат при повреждённом снимке. Не запускайте этот тест на рабочей БД.

Миграция `0009_composed_rule_catalog_70000` сохраняет снимок на 70000 правил. В пустой БД после всех миграций: 70000 правил и версий, 5 наборов, 98000 связей. Старые снимки сохраняются.

Миграция `0010_expression_rule_catalog_150000` добавляет снимок на 150000 определений. После всех миграций в пустой БД: 150000 правил, 150000 версий, 6 наборов, 248000 связей. Набор на 70000 и его версии сохранены.

Миграция `0011_coverage_20_languages` добавляет снимок на 150036 определений для
20 групп языков и форматов. После неё: 150036 правил и версий, 7 наборов и 398036
связей. Она содержит только 36 новых определений; связи 150000 прежних правил
копируются из родительского снимка внутри PostgreSQL. Старые определения и снимки
сохраняются. Генератор миграции: `node scripts/generate-coverage-migration.mjs`.
