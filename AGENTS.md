# Инструкции для агентов

## Docker и версия приложения

- Основной публикуемый образ: `shmatdmi/codesentry-sast:latest`.
- Для сборки без публикации используйте `npm run image:build`.
- Для релизной сборки всегда используйте `npm run image:publish`. Эта команда:
  1. формирует уникальную версию вида `1.1.0+build.<UTC-время>`;
  2. передаёт её в Docker через `APP_BUILD_VERSION`;
  3. собирает образ с тегом `shmatdmi/codesentry-sast:latest`;
  4. отправляет тег `latest` в Docker Hub.
- Не публикуйте релиз только через `docker compose build`: такая сборка может
  использовать прежний build ID из кэша и сама не выполняет push.
- Версия должна быть одинаковой в боковой панели, подвале, JSON/SARIF-отчётах
  и поле `version` ответа `GET /api/health`.

## Порты и развёртывание

- Внутри контейнера приложение слушает порт `3000`.
- На хосте приложение публикуется на стандартном HTTP-порту `80`:
  `${APP_PORT:-80}:3000`.
- Значение `APP_PORT` в `.env.example` должно оставаться равным `80`.
- Рабочее развёртывание находится на сервере `84.54.57.64` в каталоге
  `/opt/dcomp/sast`.
- Серверный Compose должен использовать образ `shmatdmi/codesentry-sast:latest`.
- Перед изменением серверных `docker-compose.yaml` и `.env` создавайте их
  резервные копии. Не удаляйте PostgreSQL volume и не пересоздавайте базу данных.

## Порядок публикации

1. Запустите `npm run lint` и необходимые тесты.
2. Выполните `npm run image:publish` и убедитесь, что push тега `latest` завершён.
3. На сервере выполните `docker compose pull app` в `/opt/dcomp/sast`.
4. Обновите приложение командой `docker compose up -d app`.
5. Дождитесь состояния `healthy`.
6. Проверьте внешний endpoint `http://84.54.57.64/api/health`.
7. Убедитесь, что ответ имеет статус `200`, база отмечена как `connected`, а
   версия совпадает с версией опубликованной сборки.

Не считайте развёртывание завершённым, пока внешний health endpoint на порту 80
не прошёл проверку.
